# 闲小集 · 校园二手交易平台

> 让每一件闲置，连接每一位学生。面向所有学生的二手交易集市：发布闲置、分类浏览、关键词搜索。

- 技术栈：Django 5.2 + SQLite（开发期，预留切换 MySQL）+ Bootstrap 5 + Pillow
- 状态：🚧 持续开发中（已完成：注册登录、商品发布与浏览、订单交易、收藏、商品留言）

## 已实现功能

| 模块 | 说明 |
|------|------|
| 用户系统 | 自定义用户模型（扩展手机号/头像）、注册自动登录、登录/登出、个人中心 |
| 商品发布 | 图片上传、定价（校验 >0 且低于原价）、成色、分类、交易地点 |
| 首页集市 | 商品瀑布流、关键词搜索（标题/描述）、分类筛选、分页 |
| 商品详情 | 浏览量统计（F 表达式防并发丢失）、同类好物推荐、商品留言板 |
| 订单交易 | 下单（快照价格 + 条件唯一约束防重复下单）→ 卖家确认/拒绝 → 确认收货/取消；订单中心双标签（我买到的 / 我卖出的）；交易完成自动置商品为已售出并关闭同商品其他进行中订单 |
| 商品状态 | 在售中 / 已预订 / 已售出联动展示，列表页用 Prefetch 预取进行中订单避免 N+1 查询 |
| 收藏 | 一键收藏/取消（get_or_create + 唯一约束）、我的收藏页、已售出遮罩提示 |
| 商品留言 | 详情页公开留言板，卖家回复带「卖家」标识，200 字上限 |
| 我的管理 | 我的闲置列表、编辑、删除（仅卖家本人可操作） |
| 后台管理 | Django Admin：商品/分类/订单/收藏/留言管理，订单状态可在后台直接修改 |

## 快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 初始化数据库
python manage.py migrate

# 3. 生成演示数据（6 个分类 + 8 件带封面图的商品 + 订单/留言/收藏示例）
python manage.py seed_demo

# 4. 启动开发服务器
python manage.py runserver
```

访问 http://127.0.0.1:8000 即可浏览集市。

演示账号：`不想早八` / `阿橘不吃香菜` / `图书馆钉子户` / `考研失败选手`（买家），密码见 `goods/management/commands/seed_demo.py` 中的 `DEMO_PASSWORD`。

## 项目结构

```
config/     项目配置（settings/urls）
accounts/   用户应用：注册登录、个人中心
goods/      商品应用：模型/表单/视图/管理命令
templates/  全站模板（Bootstrap 5 + 自定义蓝白渐变主题）
media/      用户上传的商品图片
```

## 设计决策

- **为什么用自定义用户模型？** 项目起步阶段就确定扩展点，避免后期迁移内置 User 表的高成本（Django 官方推荐实践）。
- **分类为什么用独立表？** 后台可随时增删分类，页面筛选复用同一份数据，对扩展开放。
- **商品分类外键为什么用 PROTECT？** 防止误删分类导致商品成为孤儿数据。
- **浏览量为什么用 F 表达式？** 自增操作在数据库层执行，避免并发请求下的更新丢失。
- **删除为什么只允许 POST？** 防止 GET 链接触发误删（CSRF 防护同样生效）。
